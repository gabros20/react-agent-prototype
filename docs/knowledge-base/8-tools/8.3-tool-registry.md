## Overview

As agent capabilities grow, tool count increases. A CMS agent might start with 5 tools and grow to 50. But LLMs have practical limits—too many tools decrease selection accuracy and consume context tokens. Beyond ~20 tools, accuracy drops noticeably.

The solution: organize tools in a registry with rich metadata, then dynamically select only relevant tools for each request using semantic search.

**Key Research Findings** (2024-2025):

-   **56% improvement in Recall@5** with vector retrieval for tool selection (LangGraph)
-   **70% reduction in execution time** with dynamic tool selection
-   **40% power consumption reduction** on edge devices with tool filtering
-   **Accuracy drops** after ~20 tools without dynamic selection

**Date Verified**: 2026-01-03

## The Problem: Tool Overload

### The Classic Challenge

An agent has 50 tools available. Each tool description is ~100 tokens. That's 5,000 tokens just for tool definitions—before the user's question. The LLM struggles to pick the right tool, often choosing a plausible-sounding but wrong option.

```
Agent Context:
- System prompt: 500 tokens
- Tool definitions: 5,000 tokens (50 tools × 100 tokens)
- Conversation history: 2,000 tokens
- User query: 50 tokens
───────────────────────────────
Total: 7,550 tokens (before response)
```

**Problems**:

-   ❌ **Token waste**: Most tools irrelevant to current query
-   ❌ **Selection accuracy drops**: LLM confused by similar-sounding tools
-   ❌ **Latency increases**: More tokens = slower processing
-   ❌ **Cost scales linearly**: Paying for irrelevant tool descriptions

### Why This Matters

-   **Accuracy**: Wrong tool selection fails the task
-   **Cost**: 50 tools costs 10x more context than 5 tools
-   **Speed**: Context processing time increases with size
-   **Scalability**: Can't just keep adding tools indefinitely

## Core Concept

### Static vs. Dynamic Tool Selection

```
STATIC SELECTION                    DYNAMIC SELECTION
(All tools, always)                 (Relevant tools, per-query)

┌─────────────────────┐            ┌─────────────────────┐
│    User Query       │            │    User Query       │
└──────────┬──────────┘            └──────────┬──────────┘
           │                                  │
           ▼                                  ▼
┌─────────────────────┐            ┌─────────────────────┐
│   All 50 Tools      │            │  Semantic Search    │
│   Sent to LLM       │            │  Tool Embeddings    │
└──────────┬──────────┘            └──────────┬──────────┘
           │                                  │
           ▼                                  ▼
┌─────────────────────┐            ┌─────────────────────┐
│  LLM Picks One      │            │  Top 5 Relevant     │
│  (50 to consider)   │            │  Tools Selected     │
└─────────────────────┘            └──────────┬──────────┘
                                              │
                                              ▼
                                   ┌─────────────────────┐
                                   │  LLM Picks One      │
                                   │  (5 to consider)    │
                                   └─────────────────────┘
```

### The Registry Pattern

```
┌─────────────────────────────────────────────────────────────┐
│                      TOOL REGISTRY                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Tool ─────────┬───── Metadata                             │
│                │                                            │
│  cms_pages_get │  category: ["cms", "read", "pages"]       │
│                │  riskLevel: "low"                          │
│                │  requiresAuth: true                        │
│                │  embedding: [0.12, 0.45, ...]             │
│                │                                            │
│  storage_upload│  category: ["storage", "write", "media"]  │
│                │  riskLevel: "medium"                       │
│                │  requiresAuth: true                        │
│                │  embedding: [0.34, 0.22, ...]             │
│                │                                            │
└─────────────────────────────────────────────────────────────┘
```

### Key Principles

1. **Centralize**: All tools in one registry, not scattered across files
2. **Enrich**: Add metadata beyond just name and description
3. **Index**: Embed tool descriptions for semantic search
4. **Filter**: Select only relevant tools per request

## Implementation Patterns

### Pattern 1: Static Tool Registry

**Use Case**: 5-20 tools where all can be sent to the LLM.

```typescript
// tools/registry.ts
import { Tool } from "ai";

// Define all tools
export const AGENT_TOOLS = {
  // CMS Tools
  cms_pages_get: getPageTool,
  cms_pages_list: listPagesTool,
  cms_pages_create: createPageTool,
  cms_pages_update: updatePageTool,
  cms_pages_delete: deletePageTool,

  // Content Tools
  cms_sections_get: getSectionTool,
  cms_sections_update: updateSectionTool,

  // Storage Tools
  storage_images_upload: uploadImageTool,
  storage_images_delete: deleteImageTool,
} as const;

// Type-safe tool names
export type ToolName = keyof typeof AGENT_TOOLS;

// Get all tools as array
export function getAllTools(): Tool[] {
  return Object.values(AGENT_TOOLS);
}
```

**Pros**:
-   ✅ Simple, no infrastructure needed
-   ✅ Type-safe tool names
-   ✅ All tools always available

**Cons**:
-   ❌ Doesn't scale beyond ~20 tools
-   ❌ No filtering capability

**When to Use**: Small tool sets (< 20 tools)

### Pattern 2: Metadata-Enriched Registry

**Use Case**: Categorize and filter tools by properties.

```typescript
// tools/metadata.ts
export interface ToolMetadata {
  name: ToolName;
  description: string;
  categories: string[];
  riskLevel: "low" | "medium" | "high" | "critical";
  requiresAuth: boolean;
  ioType: "read" | "write" | "both";
  estimatedLatency: "fast" | "medium" | "slow";
}

export const TOOL_METADATA: Record<ToolName, ToolMetadata> = {
  cms_pages_get: {
    name: "cms_pages_get",
    description: "Fetch a single page by ID or slug",
    categories: ["cms", "pages", "read"],
    riskLevel: "low",
    requiresAuth: true,
    ioType: "read",
    estimatedLatency: "fast",
  },
  cms_pages_delete: {
    name: "cms_pages_delete",
    description: "Permanently delete a page",
    categories: ["cms", "pages", "write", "destructive"],
    riskLevel: "high",
    requiresAuth: true,
    ioType: "write",
    estimatedLatency: "fast",
  },
  storage_images_upload: {
    name: "storage_images_upload",
    description: "Upload and process an image file",
    categories: ["storage", "media", "write"],
    riskLevel: "medium",
    requiresAuth: true,
    ioType: "write",
    estimatedLatency: "slow",
  },
  // ... more tools
};

// Filter by category
export function getToolsByCategory(category: string): ToolName[] {
  return Object.entries(TOOL_METADATA)
    .filter(([_, meta]) => meta.categories.includes(category))
    .map(([name]) => name as ToolName);
}

// Filter by risk level
export function getSafeTools(): ToolName[] {
  return Object.entries(TOOL_METADATA)
    .filter(([_, meta]) => meta.riskLevel === "low")
    .map(([name]) => name as ToolName);
}

// Filter read-only tools
export function getReadOnlyTools(): ToolName[] {
  return Object.entries(TOOL_METADATA)
    .filter(([_, meta]) => meta.ioType === "read")
    .map(([name]) => name as ToolName);
}
```

**Pros**:
-   ✅ Filter by any property
-   ✅ Supports role-based access
-   ✅ Easy to query

**Cons**:
-   ❌ Manual category assignment
-   ❌ Still limited for large tool sets

**When to Use**: 10-30 tools with clear categorization needs

### Pattern 3: Semantic Tool Discovery

**Use Case**: 30+ tools where semantic search finds relevant tools per query.

```typescript
// tools/discovery.ts
import { embed } from "ai";
import { cosineSimilarity } from "@/lib/math";

// Build embeddings for all tools
export async function buildToolIndex(
  tools: ToolMetadata[],
  embedder: EmbedderModel
): Promise<Map<ToolName, number[]>> {
  const embeddings = new Map<ToolName, number[]>();

  for (const tool of tools) {
    // Embed description + categories
    const text = `${tool.name}: ${tool.description}. Categories: ${tool.categories.join(", ")}`;

    const { embedding } = await embed({
      model: embedder,
      value: text,
    });

    embeddings.set(tool.name, embedding);
  }

  return embeddings;
}

// Find relevant tools for a query
export async function discoverTools(
  query: string,
  options: {
    topK: number;
    embedder: EmbedderModel;
    toolEmbeddings: Map<ToolName, number[]>;
    minSimilarity?: number;
  }
): Promise<ToolName[]> {
  // Embed the query
  const { embedding: queryEmbedding } = await embed({
    model: options.embedder,
    value: query,
  });

  // Calculate similarities
  const similarities: { name: ToolName; score: number }[] = [];

  for (const [name, toolEmbedding] of options.toolEmbeddings) {
    const score = cosineSimilarity(queryEmbedding, toolEmbedding);
    similarities.push({ name, score });
  }

  // Sort by similarity and filter
  return similarities
    .sort((a, b) => b.score - a.score)
    .filter((s) => s.score >= (options.minSimilarity ?? 0.3))
    .slice(0, options.topK)
    .map((s) => s.name);
}

// Usage in agent
async function handleQuery(query: string) {
  // Discover relevant tools (top 5)
  const relevantToolNames = await discoverTools(query, {
    topK: 5,
    embedder: openai.embedding("text-embedding-3-small"),
    toolEmbeddings: cachedToolEmbeddings,
    minSimilarity: 0.4,
  });

  // Build tool object with only relevant tools
  const relevantTools = Object.fromEntries(
    relevantToolNames.map((name) => [name, AGENT_TOOLS[name]])
  );

  // Execute agent with filtered tools
  return agent.generate({
    messages: [{ role: "user", content: query }],
    tools: relevantTools,
  });
}
```

**Pros**:
-   ✅ Scales to 100+ tools
-   ✅ Reduces token usage by 80-90%
-   ✅ Improves selection accuracy

**Cons**:
-   ❌ Requires embedding infrastructure
-   ❌ Additional latency for embedding query
-   ❌ May miss relevant tools if embeddings poor

**When to Use**: 30+ tools or token-constrained environments

### Pattern 4: Hierarchical Tool Selection

**Use Case**: Two-stage selection for very large tool sets.

```typescript
// First: Select category/domain
const TOOL_DOMAINS = {
  cms: ["cms_pages_*", "cms_sections_*", "cms_entries_*"],
  storage: ["storage_images_*", "storage_files_*"],
  users: ["users_profile_*", "users_permissions_*"],
  search: ["search_content", "search_images", "search_users"],
};

// Stage 1: LLM picks domain
const domainSchema = z.object({
  domain: z.enum(["cms", "storage", "users", "search"]),
  reasoning: z.string(),
});

const domainSelection = await generateObject({
  model,
  schema: domainSchema,
  prompt: `Given this query, which domain is most relevant?\n\nQuery: ${query}\n\nDomains:\n- cms: Page and content management\n- storage: File and image operations\n- users: User profiles and permissions\n- search: Finding content`,
});

// Stage 2: Get tools from selected domain
const domainTools = getToolsByDomain(domainSelection.object.domain);

// Stage 3: LLM uses domain-specific tools
const result = await agent.generate({
  messages: [{ role: "user", content: query }],
  tools: domainTools,
});
```

**Pros**:
-   ✅ Works with 100+ tools
-   ✅ Clear domain boundaries
-   ✅ LLM reasoning explicit

**Cons**:
-   ❌ Extra LLM call for domain selection
-   ❌ Cross-domain queries harder
-   ❌ Domain design requires thought

**When to Use**: 50+ tools with clear domain boundaries

## When to Use This Pattern

### ✅ Use When:

1. **Growing Tool Set**
    - Starting to add more than 15-20 tools
    - Planning for future tool expansion

2. **Token Constraints**
    - Cost-sensitive applications
    - Edge deployment with limited context

3. **Accuracy Issues**
    - LLM picking wrong tools frequently
    - Similar-sounding tools causing confusion

### ❌ Don't Use When:

1. **Small Tool Set**
    - 5-10 tools fits easily in context
    - Static selection is simpler

2. **Uniform Tool Usage**
    - All tools needed for every query
    - No filtering benefit

### Decision Matrix

| Tool Count | Recommended Approach |
|------------|---------------------|
| 1-10 | Static registry |
| 10-30 | Metadata + category filtering |
| 30-50 | Semantic discovery (top-K) |
| 50+ | Hierarchical (domain → tools) |

## Production Best Practices

### 1. Cache Tool Embeddings

Computing embeddings is slow. Pre-compute at startup and cache.

```typescript
// At application startup
const toolEmbeddings = await buildToolIndex(
  Object.values(TOOL_METADATA),
  openai.embedding("text-embedding-3-small")
);

// Cache in memory or Redis
await redis.set("tool:embeddings", JSON.stringify([...toolEmbeddings]));
```

**Impact**: Reduces per-request latency by 100-500ms

### 2. Include Always-Available Tools

Some tools should always be available regardless of query (e.g., help, cancel).

```typescript
const ALWAYS_INCLUDE: ToolName[] = ["help", "cancel_operation", "get_status"];

async function getToolsForQuery(query: string): Promise<Tool[]> {
  const discovered = await discoverTools(query, { topK: 5 });
  const allNames = [...new Set([...ALWAYS_INCLUDE, ...discovered])];
  return allNames.map((name) => AGENT_TOOLS[name]);
}
```

### 3. Common Pitfalls

#### ❌ Pitfall 1: Over-Filtering

Setting topK too low misses relevant tools.

**Solution**: Start with topK=5-7, monitor tool selection accuracy, adjust based on data.

#### ❌ Pitfall 2: Poor Tool Descriptions for Embedding

Embedding quality depends on description quality. "Gets a page" embeds worse than "Fetch a page by ID or slug, returning title, content, and metadata."

**Solution**: Write descriptions for both LLM selection AND embedding quality. Be specific.

#### ❌ Pitfall 3: No Fallback for Discovery Failures

Semantic search returns no results for novel queries.

**Solution**: Always have a fallback. If discovery returns < 2 tools, include a broader set or ask clarifying question.

## Key Takeaways

1. **Centralize tools in a registry**—single source of truth for all tools
2. **Add metadata beyond name/description**—categories, risk levels, I/O type
3. **Use semantic discovery for 30+ tools**—56% improvement in selection accuracy
4. **Cache embeddings**—pre-compute at startup, not per-request
5. **Include always-available tools**—help, cancel, status should always be present
