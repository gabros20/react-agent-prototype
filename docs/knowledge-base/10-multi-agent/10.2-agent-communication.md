## Overview

Agent communication enables multiple agents to collaborate on complex tasks by sharing information, coordinating actions, and resolving conflicts. The choice between message passing and shared state fundamentally shapes your multi-agent architecture.

**Message passing** treats agents as independent actors exchanging messages—good for loose coupling but requires explicit coordination. **Shared state** gives agents access to a common knowledge base—good for complex coordination but requires concurrency control.

**Key Research Findings** (2024-2025):

-   **Blackboard pattern improves task success by 13-57%** over baseline multi-agent (ACL 2025)
-   **Multi-agent systems use 15x more tokens** than single-agent chat
-   **67% of tokens wasted** in naive context sharing (no isolation)
-   **MCP (Model Context Protocol)** emerged as industry standard (November 2024)

**Date Verified**: 2026-01-04

## The Problem: Agents That Can't Collaborate

### The Classic Challenge

Multiple agents work on a task but can't share information effectively:

```
Agent A: "I found the user's account balance: $5,000"
Agent B: "What's the user's account balance?" (asks again)
Agent C: "Processing refund..." (doesn't know balance)

Problems:
- Duplicated work (each agent queries same data)
- Inconsistent state (agents have different views)
- Wasted tokens (redundant information gathering)
```

**Problems**:

-   ❌ **Duplicated effort**: Each agent independently gathers same information
-   ❌ **Inconsistent state**: Agents have conflicting views of reality
-   ❌ **Token explosion**: Same information repeated across agent contexts
-   ❌ **No coordination**: Agents step on each other's work

### Why This Matters

-   **Cost**: 15x token usage without proper communication design
-   **Correctness**: Inconsistent state leads to wrong decisions
-   **Latency**: Redundant work increases end-to-end time
-   **Debugging**: Hard to trace information flow across agents

```
Token Usage Comparison:

Single Agent Chat:
  User message: 50 tokens
  Agent response: 200 tokens
  Total: 250 tokens

Multi-Agent (Naive):
  Supervisor: 500 tokens
  Agent A context: 800 tokens
  Agent B context: 800 tokens
  Agent C context: 800 tokens

  Supervisor: 300 tokens
  Shared state: 400 tokens (not duplicated)
  Agent-specific: 200 tokens × 3
  Total: 1,300 tokens (5x)
```

**Key Insight**: Context isolation and summarization can reduce multi-agent token usage by 60-70%.

## Message Passing Patterns

### Pattern 1: Direct Agent-to-Agent

**Use Case**: Simple handoffs between two agents.

```
Agent A                    Agent B
   │                          │
   │──── handoff_message ────▶│
   │                          │
   │◀──── result_message ─────│
```

**Handoff Message Structure**:
```typescript
interface AgentHandoff {
  fromAgent: string;
  toAgent: string;
  task: string;
  context: {
    summary: string;      // Compressed context
    keyFacts: string[];   // Essential information
    constraints: string[];
  };
  expectation: string;    // What receiving agent should do
}
```

**Pros**:
-   ✅ Simple, explicit communication
-   ✅ Easy to trace and debug
-   ✅ Low overhead

**Cons**:
-   ❌ Doesn't scale to many agents
-   ❌ Sender must know receiver

### Pattern 2: Broadcast (Pub-Sub)

**Use Case**: One agent's output needed by multiple agents.

```
                    ┌─────────┐
                    │ MESSAGE │
                    │  BUS    │
                    └────┬────┘
                         │
         ┌───────────────┼───────────────┐
         │               │               │
         ▼               ▼               ▼
    ┌─────────┐    ┌─────────┐    ┌─────────┐
    │Agent A  │    │Agent B  │    │Agent C  │
    │(publish)│    │(subscribe)   │(subscribe)
    └─────────┘    └─────────┘    └─────────┘
```

**Topics Example**:
```
Topics:
├── research.complete     → Writer, Reviewer subscribe
├── code.generated        → Tester, Reviewer subscribe
├── error.detected        → Debug agent subscribes
└── approval.required     → Human interface subscribes
```

**Pros**:
-   ✅ Decouples producers from consumers
-   ✅ Easy to add new subscribers
-   ✅ Natural for event-driven workflows

**Cons**:
-   ❌ Message ordering not guaranteed
-   ❌ Harder to trace full flow
-   ❌ Requires message bus infrastructure

### Pattern 3: Request-Response

**Use Case**: Agent needs specific information from another agent.

```
Agent A                    Agent B
   │                          │
   │──── request(query) ─────▶│
   │         (blocks)         │
   │◀──── response(data) ─────│
   │                          │
```

**When to Use**:
-   Agent needs result before continuing
-   Synchronous coordination required
-   Simple query-response patterns

**When to Avoid**:
-   Long-running operations (use async)
-   Fire-and-forget scenarios (use events)

## Shared State Patterns

### Pattern 1: Blackboard Pattern

**Use Case**: Complex coordination requiring shared knowledge.

```
┌───────────────────────────────────────────┐
│              BLACKBOARD                   │
│                                           │
│  facts: {                                 │
│    user_id: "123",                        │
│    account_balance: 5000,                 │
│    pending_transactions: [...]            │
│  }                                        │
│                                           │
│  status: {                                │
│    research: "complete",                  │
│    analysis: "in_progress",               │
│    writing: "pending"                     │
│  }                                        │
│                                           │
│  artifacts: {                             │
│    research_summary: "...",               │
│    draft_document: "..."                  │
│  }                                        │
└───────────────────────────────────────────┘
         │           │           │
         ▼           ▼           ▼
    ┌─────────┐ ┌─────────┐ ┌─────────┐
    │Research │ │Analysis │ │ Writer  │
    │ Agent   │ │  Agent  │ │  Agent  │
    └─────────┘ └─────────┘ └─────────┘
```

**Research Finding (ACL 2025)**: Blackboard pattern improves multi-agent task success by 13-57% compared to message-only approaches.

**Blackboard Sections**:
-   **Facts**: Shared knowledge base (read by all)
-   **Status**: Agent progress tracking
-   **Artifacts**: Intermediate outputs
-   **Tasks**: Pending work items

**Pros**:
-   ✅ All agents see consistent state
-   ✅ Natural for iterative refinement
-   ✅ Easy to add new knowledge

**Cons**:
-   ❌ Requires concurrency control
-   ❌ Can become cluttered
-   ❌ All agents coupled to state schema

### Pattern 2: Scoped Shared State

**Use Case**: Limit what each agent can see/modify.

```
┌─────────────────────────────────────────────────────┐
│                   SHARED STATE                      │
├──────────────────┬──────────────────┬───────────────┤
│   Global Scope   │   Team Scope     │  Agent Scope  │
│   (read-only)    │   (team access)  │  (private)    │
├──────────────────┼──────────────────┼───────────────┤
│                  │                  │               │
│  user_context    │  research_team:  │  agent_a:     │
│  system_config   │    findings      │    scratchpad │
│  constraints     │    sources       │    temp_data  │
│                  │                  │               │
│                  │  writing_team:   │  agent_b:     │
│                  │    drafts        │    scratchpad │
│                  │    feedback      │               │
└──────────────────┴──────────────────┴───────────────┘
```

**Access Control**:
```
Permission Matrix:
                    Global   Team    Private
Research Agent      READ     R/W     R/W
Writer Agent        READ     READ    R/W
Reviewer Agent      READ     READ    R/W
```

**Benefit**: Prevents token explosion by limiting context to relevant scope.

### Pattern 3: Memory Architecture

**Use Case**: Short-term + long-term memory separation.

```
┌──────────────────────────────────────────────┐
│              MEMORY ARCHITECTURE             │
├──────────────────────────────────────────────┤
│                                              │
│  SHORT-TERM (Thread-Scoped)                  │
│  ├── Current conversation                    │
│  ├── Task progress                           │
│  └── Temporary calculations                  │
│                                              │
│  LONG-TERM (Persistent)                      │
│  ├── User preferences                        │
│  ├── Historical interactions                 │
│  └── Learned patterns                        │
│                                              │
│  WORKING MEMORY (Active Context)             │
│  ├── Currently relevant facts                │
│  ├── Active goals                            │
│  └── Pending actions                         │
│                                              │
└──────────────────────────────────────────────┘
```

**Implementation with LangGraph**:
```python
# Short-term: Checkpointer (thread-scoped)
checkpointer = PostgresSaver(conn)

# Long-term: Store (cross-thread)
store = PostgresStore(conn)

app = graph.compile(
    checkpointer=checkpointer,  # Per-conversation state
    store=store                 # Persistent memories
)
```

### Reactive Agent Pattern

**Flow**:
```
Event Occurs
    │
    ▼
┌─────────────────┐
│ Event Router    │
│                 │
│ Matches event   │
│ to agent(s)     │
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
    ▼         ▼
Agent A    Agent B
(handles)  (observes)
```

**Example Events**:
```typescript
type AgentEvent =
  | { type: 'task.assigned'; agentId: string; task: Task }
  | { type: 'task.completed'; agentId: string; result: Result }
  | { type: 'error.occurred'; agentId: string; error: Error }
  | { type: 'approval.required'; action: Action; context: Context }
  | { type: 'state.changed'; key: string; value: unknown };
```

## Conflict Resolution

### When Agents Disagree

```
Scenario: Research Agent and Writer Agent disagree on facts

Research Agent: "Company revenue is $10M"
Writer Agent: "I found revenue is $12M"

Resolution Strategies:
1. Voting (multiple agents vote)
2. Authority (designated agent decides)
3. Escalation (human decides)
4. Evidence-based (agent with sources wins)
```

### Voting vs Consensus

**Research Finding (ACL 2025)**:
-   **Voting**: 13.2% better for reasoning tasks (3.38 rounds average)
-   **Consensus**: 2.8% better for knowledge tasks (1.42 rounds average)

```
Voting Pattern:
┌─────────────────────────────────────────────┐
│  Question: "Is the data valid?"             │
│                                             │
│  Agent A: YES (confidence: 0.9)             │
│  Agent B: YES (confidence: 0.7)             │
│  Agent C: NO  (confidence: 0.6)             │
│                                             │
│  Result: YES (weighted: 0.77)               │
└─────────────────────────────────────────────┘

Consensus Pattern:
┌─────────────────────────────────────────────┐
│  Round 1: Agents share positions            │
│  Round 2: Agents respond to disagreements   │
│  Round 3: Final positions                   │
│                                             │
│  If consensus reached: Proceed              │
│  If not: Escalate to supervisor             │
└─────────────────────────────────────────────┘
```

### Priority and Authority

**When voting isn't appropriate**:
```
Authority Hierarchy:
├── Safety Agent: Veto power on risky actions
├── Supervisor: Tie-breaker authority
├── Domain Expert: Priority in specialty area
└── General Agent: Default level
```

**Use Authority When**:
-   Safety-critical decisions
-   Clear domain expertise exists
-   Speed more important than consensus

## Framework Integration

### LangGraph Shared State

```python
from langgraph.graph import StateGraph, START, END
from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages

class SharedState(TypedDict):
    messages: Annotated[list, add_messages]

    # Shared facts (all agents read/write)
    facts: dict

    # Agent-specific scratchpads
    research_notes: str
    writing_draft: str

    # Coordination state
    current_agent: str
    completed_stages: list[str]

def research_node(state: SharedState) -> dict:
    # Read from shared facts
    user_id = state["facts"].get("user_id")

    # Do research...
    findings = research(user_id)

    # Update shared state
    return {
        "facts": {**state["facts"], "research_findings": findings},
        "research_notes": "Completed research on...",
        "completed_stages": state["completed_stages"] + ["research"]
    }

graph = StateGraph(SharedState)
graph.add_node("research", research_node)
graph.add_node("write", write_node)
# ... build graph
```

### AI SDK Context Sharing

```typescript
import { ToolLoopAgent } from 'ai';

// Shared context object (passed to all agents)
interface MultiAgentContext {
  sessionId: string;
  sharedState: Map<string, unknown>;
  eventBus: EventEmitter;
}

// Each agent receives same context
const researchAgent = new ToolLoopAgent({
  model: openai('gpt-4-turbo'),
  tools: {
    updateSharedState: tool({
      description: 'Update shared state',
      parameters: z.object({
        key: z.string(),
        value: z.unknown()
      }),
      execute: async ({ key, value }, { experimental_context }) => {
        const ctx = experimental_context as MultiAgentContext;
        ctx.sharedState.set(key, value);
        ctx.eventBus.emit('state.changed', { key, value });
        return { success: true };
      }
    }),
    readSharedState: tool({
      description: 'Read from shared state',
      parameters: z.object({ key: z.string() }),
      execute: async ({ key }, { experimental_context }) => {
        const ctx = experimental_context as MultiAgentContext;
        return ctx.sharedState.get(key);
      }
    })
  }
});

// Orchestrator passes same context to all agents
async function orchestrate(prompt: string) {
  const sharedContext: MultiAgentContext = {
    sessionId: crypto.randomUUID(),
    sharedState: new Map(),
    eventBus: new EventEmitter()
  };

  // All agents share this context
  await researchAgent.generate({
    prompt,
    experimental_context: sharedContext
  });
  await writerAgent.generate({
    prompt: 'Write based on research',
    experimental_context: sharedContext
  });
}
```

## Production Best Practices

### 1. Context Isolation

**Prevent token waste** by scoping context:

```
❌ Bad: All agents see all context
   Research context: 2000 tokens
   Writing context: 2000 tokens
   Review context: 2000 tokens
   Each agent sees: 6000 tokens
   Total: 18,000 tokens (3 agents × 6000)

✅ Good: Scoped context per agent
   Shared base: 500 tokens
   Research specific: 1500 tokens
   Writing specific: 1500 tokens
   Review specific: 1500 tokens
   Total: 5,000 tokens
```

### 2. State Versioning

**Track state changes** for debugging:

```typescript
interface VersionedState {
  version: number;
  timestamp: Date;
  updatedBy: string;
  data: Record<string, unknown>;
  previous?: VersionedState;
}

function updateState(
  current: VersionedState,
  updates: Record<string, unknown>,
  agentId: string
): VersionedState {
  return {
    version: current.version + 1,
    timestamp: new Date(),
    updatedBy: agentId,
    data: { ...current.data, ...updates },
    previous: current
  };
}
```

### 3. Atomic Operations

**Prevent race conditions** in shared state:

```typescript
// Use atomic operations for concurrent updates
async function atomicUpdate(
  store: StateStore,
  key: string,
  updater: (current: unknown) => unknown
): Promise<void> {
  let success = false;
  while (!success) {
    const current = await store.get(key);
    const newValue = updater(current);
    success = await store.compareAndSwap(key, current, newValue);
  }
}
```

### Common Pitfalls

#### ❌ Pitfall 1: Unbounded Context Growth

Agents keep adding to shared state without cleanup.

**Solution**: Implement context compaction, set TTLs, summarize old entries.

#### ❌ Pitfall 2: Circular Dependencies

Agent A waits for Agent B, which waits for Agent A.

**Solution**: DAG-based dependencies, timeout with escalation.

#### ❌ Pitfall 3: No Conflict Resolution

Agents overwrite each other's state silently.

**Solution**: Version checking, merge policies, conflict handlers.

## Key Takeaways

1. **Message passing for loose coupling**—agents stay independent, explicit communication
2. **Shared state for complex coordination**—blackboard pattern improves success by 13-57%
3. **Context isolation prevents 67% token waste**—scope aggressively
4. **15x token overhead is real**—budget for multi-agent communication costs
5. **MCP is the emerging standard**—use for inter-agent resource sharing
6. **Voting for reasoning, consensus for knowledge**—choose conflict resolution by task type
