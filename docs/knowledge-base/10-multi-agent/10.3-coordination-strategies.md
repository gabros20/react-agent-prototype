## Overview

Coordination strategies determine how agents execute: one after another (sequential), simultaneously (parallel), in tree structures (hierarchical), or through negotiation (peer-to-peer). The right strategy depends on task dependencies, latency requirements, and complexity.

Modern frameworks like LangGraph represent coordination as **graphs** where nodes are agents and edges define execution flow. This enables complex patterns like conditional routing, cycles for iteration, and dynamic fan-out.

**Key Research Findings** (2024-2025):

-   **Supervisor pattern improves performance by 50%** compared to flat collaboration
-   **Parallel execution reduces latency by 60-70%** for independent tasks
-   **GPT-4o-mini achieves 84.13% task scores** with graph-based coordination
-   **Enterprise AI orchestration market**: $5.8B (2024) → $48.7B projected (2034)

**Date Verified**: 2026-01-04

## The Problem: Uncoordinated Agents

### The Classic Challenge

Multiple agents work on a task without clear execution strategy:

```
Uncoordinated Execution:

Agent A: "I'll analyze the data"
Agent B: "I'll analyze the data too" (duplicate)
Agent C: "I need A's results but A isn't done yet" (blocked)

Results:
- Duplicated work (A and B do same thing)
- Blocked execution (C waits indefinitely)
- Inconsistent outputs (no merge strategy)
- Wasted resources (3x compute for same result)
```

**Problems**:

-   ❌ **Race conditions**: Agents compete for same resources
-   ❌ **Deadlocks**: Agents wait for each other indefinitely
-   ❌ **Duplicated work**: No awareness of what others are doing
-   ❌ **Inconsistent outputs**: No strategy to merge results

### Why This Matters

-   **Reliability**: Uncoordinated agents fail unpredictably
-   **Efficiency**: 2-3x wasted compute without proper coordination
-   **Latency**: Sequential bottlenecks in parallel-capable workflows
-   **Correctness**: Merge conflicts produce wrong results

## Core Concept

### Coordination as Graphs

```
Graph-Based Coordination:

Nodes = Agents (or agent functions)
Edges = Execution flow (sequential, conditional, parallel)

     ┌─────────┐
     │  START  │
     └────┬────┘
          │
          ▼
     ┌─────────┐
     │ Agent A │
     └────┬────┘
          │
     ┌────┴────┐
     │         │
     ▼         ▼
┌─────────┐ ┌─────────┐
│ Agent B │ │ Agent C │  (Parallel)
└────┬────┘ └────┬────┘
     │           │
     └─────┬─────┘
           │
           ▼
     ┌─────────┐
     │ Agent D │
     └────┬────┘
          │
          ▼
     ┌─────────┐
     │   END   │
     └─────────┘
```

### Coordination Primitives

```
Four Primary Patterns:

1. SEQUENTIAL (Pipeline)
   A → B → C → D
   Use: Dependent stages, data transformation

2. PARALLEL (Fan-Out/Fan-In)
   A → [B, C, D] → E
   Use: Independent tasks, latency reduction

3. HIERARCHICAL (Tree)
   Supervisor → [Team1, Team2] → [Workers...]
   Use: Complex domains, delegation

4. CONDITIONAL (Routing)
   A → decision → B or C
   Use: Dynamic flow, error handling
```

## Sequential Coordination

### Pattern: Pipeline

**Use Case**: Each stage depends on previous stage's output.

```
Sequential Pipeline:

┌─────────┐     ┌─────────┐     ┌─────────┐     ┌─────────┐
│ Research│────▶│ Analyze │────▶│  Write  │────▶│ Review  │
│         │     │         │     │         │     │         │
│ Output: │     │ Input:  │     │ Input:  │     │ Input:  │
│ raw data│     │ raw data│     │ analysis│     │ draft   │
└─────────┘     │ Output: │     │ Output: │     │ Output: │
                │ analysis│     │ draft   │     │ final   │
                └─────────┘     └─────────┘     └─────────┘
```

**Implementation Pattern**:

```typescript
// AI SDK Sequential Chain
async function sequentialPipeline(input: string) {
  // Stage 1: Research
  const research = await researchAgent.generate({
    prompt: `Research: ${input}`
  });

  // Stage 2: Analyze (depends on research)
  const analysis = await analyzeAgent.generate({
    prompt: `Analyze: ${research.content}`
  });

  // Stage 3: Write (depends on analysis)
  const draft = await writeAgent.generate({
    prompt: `Write based on: ${analysis.content}`
  });

  // Stage 4: Review (depends on draft)
  const final = await reviewAgent.generate({
    prompt: `Review and improve: ${draft.content}`
  });

  return final.content;
}
```

**Pros**:
-   ✅ Simple to implement and debug
-   ✅ Clear data dependencies
-   ✅ Predictable execution order

**Cons**:
-   ❌ Slowest pattern (no parallelism)
-   ❌ Single point of failure (one agent fails = pipeline fails)
-   ❌ Resource underutilization

### When to Use Sequential

-   **Data transformation pipelines**: Each stage modifies data
-   **Approval workflows**: Human reviews between stages
-   **Learning/refinement loops**: Output improves each iteration
-   **Resource constraints**: Can only run one agent at a time

## Parallel Coordination

### Pattern: Fan-Out/Fan-In

**Use Case**: Independent tasks that can run simultaneously.

```
Fan-Out/Fan-In:

              ┌─────────────┐
              │   INIT      │
              │ (distribute)│
              └──────┬──────┘
                     │
        ┌────────────┼────────────┐
        │            │            │
        ▼            ▼            ▼
   ┌─────────┐  ┌─────────┐  ┌─────────┐
   │ Worker  │  │ Worker  │  │ Worker  │
   │    A    │  │    B    │  │    C    │
   └────┬────┘  └────┬────┘  └────┬────┘
        │            │            │
        └────────────┼────────────┘
                     │
                     ▼
              ┌─────────────┐
              │ AGGREGATOR  │
              │ (combine)   │
              └─────────────┘
```

**Implementation Pattern**:

```typescript
// AI SDK Parallel Execution
async function parallelFanOut(tasks: string[]) {
  // Fan-out: Execute all workers in parallel
  const results = await Promise.all(
    tasks.map(task =>
      workerAgent.generate({ prompt: task })
    )
  );

  // Fan-in: Aggregate results
  const aggregated = await aggregatorAgent.generate({
    prompt: `Synthesize these results:\n${
      results.map((r, i) => `Result ${i + 1}: ${r.content}`).join('\n')
    }`
  });

  return aggregated.content;
}
```

**Result Aggregation Strategies**:

```
Aggregation Approaches:

1. Synthesis (LLM combines)
   [Result A, Result B, Result C] → LLM → Combined summary

2. Voting (majority wins)
   [Yes, Yes, No] → Yes (2/3 majority)

3. Concatenation (simple merge)
   [Part A, Part B, Part C] → "Part A\nPart B\nPart C"

4. Structured (schema-based)
   [{data: A}, {data: B}] → {combined: [A, B]}
```

**Pros**:
-   ✅ 60-70% latency reduction for independent tasks
-   ✅ Full resource utilization
-   ✅ Natural for search/research tasks

**Cons**:
-   ❌ Requires aggregation strategy
-   ❌ All-or-nothing (one failure can block)
-   ❌ Higher peak resource usage

### When to Use Parallel

-   **Multi-source research**: Search multiple databases simultaneously
-   **Multi-perspective analysis**: Get different agent viewpoints
-   **Batch processing**: Process many items independently
-   **Latency-critical**: Need results fast

## Hierarchical Coordination

### Pattern: Manager-Worker

**Use Case**: Complex tasks requiring delegation and synthesis.

```
Hierarchical Structure:

                ┌─────────────┐
                │  SUPERVISOR │
                │  (Manager)  │
                └──────┬──────┘
                       │
           ┌───────────┼───────────┐
           │           │           │
           ▼           ▼           ▼
      ┌─────────┐ ┌─────────┐ ┌─────────┐
      │ Team A  │ │ Team B  │ │ Team C  │
      │ Lead    │ │ Lead    │ │ Lead    │
      └────┬────┘ └────┬────┘ └────┬────┘
           │           │           │
       ┌───┴───┐   ┌───┴───┐   ┌───┴───┐
       │       │   │       │   │       │
       ▼       ▼   ▼       ▼   ▼       ▼
    Worker  Worker Worker Worker Worker Worker
```

**Research Finding**: Supervisor pattern improves multi-agent performance by 50% compared to flat collaboration.

**Implementation Pattern**:

```typescript
// Hierarchical with team leads
async function hierarchicalExecution(task: string) {
  // Supervisor creates plan
  const { object: plan } = await generateObject({
    model: supervisorModel,
    schema: z.object({
      teams: z.array(z.object({
        name: z.string(),
        tasks: z.array(z.string())
      }))
    }),
    prompt: `Break down task into team assignments: ${task}`
  });

  // Team leads execute in parallel
  const teamResults = await Promise.all(
    plan.teams.map(async (team) => {
      // Team lead coordinates workers
      const workerResults = await Promise.all(
        team.tasks.map(t => workerAgent.generate({ prompt: t }))
      );

      // Team lead synthesizes
      return teamLeadAgent.generate({
        prompt: `Synthesize team ${team.name} results: ${
          workerResults.map(r => r.content).join('\n')
        }`
      });
    })
  );

  // Supervisor synthesizes final result
  return supervisorAgent.generate({
    prompt: `Final synthesis from all teams: ${
      teamResults.map(r => r.content).join('\n')
    }`
  });
}
```

**Pros**:
-   ✅ Scales to many agents
-   ✅ Natural domain boundaries
-   ✅ Clear accountability (each level owns its scope)

**Cons**:
-   ❌ Multiple hops increase latency
-   ❌ Supervisor bottleneck at each level
-   ❌ Complex to implement correctly

### When to Use Hierarchical

-   **Large agent teams (6+)**: Need organizational structure
-   **Domain specialization**: Teams focus on different areas
-   **Enterprise workflows**: Maps to organizational structure
-   **Complex synthesis**: Multiple levels of aggregation needed

## Peer-to-Peer Coordination

### Pattern: Agent Negotiation

**Use Case**: Decentralized decision-making without supervisor.

```
Peer-to-Peer Negotiation:

   Agent A ◀────────▶ Agent B
       ▲                 ▲
       │                 │
       │    negotiate    │
       │                 │
       ▼                 ▼
   Agent C ◀────────▶ Agent D
```

**Negotiation Protocol**:
```
Round 1: Agents share proposals
Round 2: Agents critique others' proposals
Round 3: Agents update based on feedback
Round 4: Vote or consensus on final decision
```

**Contract Net Protocol**:
```
Task Announcement → Agents bid → Best bid wins → Execute

Manager: "Need data analysis task completed"
Agent A: "I can do it in 3 steps, confidence 0.8"
Agent B: "I can do it in 5 steps, confidence 0.9"
Agent C: "I can do it in 2 steps, confidence 0.6"

Winner: Agent B (highest confidence)
```

**Pros**:
-   ✅ No single point of failure
-   ✅ Agents self-organize
-   ✅ Robust to agent failures

**Cons**:
-   ❌ Harder to debug (no clear control flow)
-   ❌ May not converge (infinite negotiation)
-   ❌ Higher communication overhead

### When to Use Peer-to-Peer

-   **Distributed systems**: No central coordinator available
-   **Fault tolerance**: System must survive agent failures
-   **Emergent behavior**: Exploration over optimization
-   **Research/experimentation**: Testing collaborative dynamics

## LangGraph Workflow Patterns

### StateGraph Fundamentals

```python
from langgraph.graph import StateGraph, START, END
from typing import Annotated, TypedDict
from langgraph.graph.message import add_messages

class WorkflowState(TypedDict):
    messages: Annotated[list, add_messages]
    current_stage: str
    results: dict

# Define nodes (agent functions)
def research_node(state: WorkflowState) -> dict:
    result = research_llm.invoke(state["messages"])
    return {
        "messages": [result],
        "current_stage": "research_complete",
        "results": {**state["results"], "research": result.content}
    }

def write_node(state: WorkflowState) -> dict:
    result = writer_llm.invoke(state["messages"])
    return {
        "messages": [result],
        "current_stage": "writing_complete"
    }

# Build graph
graph = StateGraph(WorkflowState)
graph.add_node("research", research_node)
graph.add_node("write", write_node)

# Define edges
graph.add_edge(START, "research")
graph.add_edge("research", "write")
graph.add_edge("write", END)

app = graph.compile()
```

### Conditional Routing

```python
from typing import Literal

def route_by_intent(state: WorkflowState) -> Literal["math", "research", "write"]:
    """Route based on current state."""
    last_message = state["messages"][-1].content.lower()

    if "calculate" in last_message:
        return "math"
    elif "search" in last_message or "find" in last_message:
        return "research"
    else:
        return "write"

graph = StateGraph(WorkflowState)
graph.add_node("math", math_node)
graph.add_node("research", research_node)
graph.add_node("write", write_node)
graph.add_node("router", router_node)

# Conditional edges from router
graph.add_conditional_edges(
    "router",
    route_by_intent,
    {
        "math": "math",
        "research": "research",
        "write": "write"
    }
)

graph.add_edge(START, "router")
graph.add_edge("math", END)
graph.add_edge("research", END)
graph.add_edge("write", END)
```

### Parallel Execution with Fan-Out

```python
# Multiple edges from one node = parallel execution
graph = StateGraph(WorkflowState)
graph.add_node("init", init_node)
graph.add_node("worker_a", worker_a_node)
graph.add_node("worker_b", worker_b_node)
graph.add_node("worker_c", worker_c_node)
graph.add_node("aggregate", aggregate_node)

# Fan-out: init spawns parallel workers
graph.add_edge("init", "worker_a")
graph.add_edge("init", "worker_b")
graph.add_edge("init", "worker_c")

# Fan-in: all workers converge to aggregator
graph.add_edge("worker_a", "aggregate")
graph.add_edge("worker_b", "aggregate")
graph.add_edge("worker_c", "aggregate")

graph.add_edge(START, "init")
graph.add_edge("aggregate", END)
```

### Subgraph Composition

```python
# Create team subgraphs
research_team = StateGraph(TeamState)
research_team.add_node("lead", research_lead_node)
research_team.add_node("worker1", research_worker1)
research_team.add_node("worker2", research_worker2)
# ... build research team graph
research_subgraph = research_team.compile()

writing_team = StateGraph(TeamState)
# ... build writing team graph
writing_subgraph = writing_team.compile()

# Main graph uses subgraphs as nodes
main_graph = StateGraph(MainState)
main_graph.add_node("supervisor", supervisor_node)
main_graph.add_node("research_team", research_subgraph)
main_graph.add_node("writing_team", writing_subgraph)

main_graph.add_edge(START, "supervisor")
main_graph.add_conditional_edges(
    "supervisor",
    route_to_team,
    {"research": "research_team", "writing": "writing_team"}
)
```

### Cycles for Iteration

```python
def should_continue(state: WorkflowState) -> Literal["continue", "end"]:
    """Check if we should iterate again."""
    if state.get("iteration_count", 0) >= 3:
        return "end"
    if state.get("quality_score", 0) >= 0.9:
        return "end"
    return "continue"

graph = StateGraph(WorkflowState)
graph.add_node("generate", generate_node)
graph.add_node("critique", critique_node)
graph.add_node("refine", refine_node)

graph.add_edge(START, "generate")
graph.add_edge("generate", "critique")
graph.add_conditional_edges(
    "critique",
    should_continue,
    {
        "continue": "refine",
        "end": END
    }
)
graph.add_edge("refine", "generate")  # Cycle back
```

## When to Use Each Strategy

### Decision Matrix

| Situation | Strategy | Why |
|-----------|----------|-----|
| Dependent stages (A needs B's output) | Sequential | Data dependencies require ordering |
| Independent tasks | Parallel | Reduce latency, maximize throughput |
| 6+ agents with domain groupings | Hierarchical | Manageable structure, clear ownership |
| Latency critical (<3s) | Parallel + Caching | Minimize total time |
| Complex approval workflows | Sequential + HITL | Human checkpoints between stages |
| Research/exploration | Peer-to-peer | Diverse perspectives, emergent insights |
| Dynamic routing needed | Conditional | Handle multiple paths based on input |
| Iterative refinement | Cycles | Generate → Critique → Refine loop |

### Pattern Selection Flowchart

```
Start
  │
  ▼
Are tasks dependent?
  ├── Yes → Sequential
  │
  ├── No → Can run in parallel?
  │         ├── Yes → Parallel (fan-out/fan-in)
  │         └── No → Sequential
  │
Need human approval?
  ├── Yes → Add HITL interrupts
  │
Need iteration?
  ├── Yes → Add cycles
  │
6+ agents?
  ├── Yes → Hierarchical
  │
Dynamic routing?
  ├── Yes → Conditional edges
  │
  ▼
 Done
```

## Production Best Practices

### 1. Timeout at Every Level

**Prevent runaway coordination**:

```typescript
const TIMEOUTS = {
  agent: 30_000,      // Single agent execution
  team: 120_000,      // Team coordination
  workflow: 300_000   // Full workflow
};

async function withTimeout<T>(
  promise: Promise<T>,
  ms: number
): Promise<T> {
  const timeout = new Promise<never>((_, reject) =>
    setTimeout(() => reject(new Error('Timeout')), ms)
  );
  return Promise.race([promise, timeout]);
}
```

### 2. Graceful Degradation

**Fallback when coordination fails**:

```typescript
async function resilientWorkflow(task: string) {
  try {
    // Try multi-agent
    return await multiAgentWorkflow(task);
  } catch (error) {
    console.warn('Multi-agent failed, falling back to single agent');
    // Fallback to single agent
    return await singleAgent.generate({ prompt: task });
  }
}
```

### 3. Observability Per Stage

**Track each coordination step**:

```
Trace Structure:
├── workflow_id: "wf-123"
├── stages:
│   ├── research:
│   │   ├── start: 1704000000
│   │   ├── end: 1704000005
│   │   ├── tokens: 1500
│   │   └── status: "success"
│   ├── parallel_analysis:
│   │   ├── worker_a: { tokens: 800, status: "success" }
│   │   ├── worker_b: { tokens: 750, status: "success" }
│   │   └── worker_c: { tokens: 900, status: "timeout" }
│   └── aggregate:
│       ├── tokens: 500
│       └── status: "partial" (only 2/3 results)
└── total:
    ├── duration: 12.5s
    ├── tokens: 4450
    └── status: "completed_with_warnings"
```

### Common Pitfalls

#### ❌ Pitfall 1: Over-Parallelization

Running everything in parallel when there are hidden dependencies.

**Solution**: Map dependencies first, parallelize only truly independent work.

#### ❌ Pitfall 2: Supervisor Bottleneck

All decisions through one supervisor creates latency.

**Solution**: Hierarchical teams with local decision authority.

#### ❌ Pitfall 3: No Circuit Breaker

One failing agent blocks entire workflow.

**Solution**: Timeouts, fallbacks, partial results.

## Key Takeaways

1. **Sequential for dependencies**—use when stages depend on previous output
2. **Parallel for throughput**—60-70% latency reduction for independent tasks
3. **Hierarchical for scale**—50% improvement over flat collaboration
4. **LangGraph for flexibility**—conditional routing, cycles, checkpointing built-in
5. **Always add timeouts**—runaway coordination is expensive
6. **Graceful degradation**—fallback to simpler patterns on failure

**Quick Implementation Checklist**:

-   [ ] Map task dependencies (what depends on what?)
-   [ ] Identify parallel opportunities (independent tasks)
-   [ ] Choose coordination pattern based on requirements
-   [ ] Add timeouts at every level
-   [ ] Implement graceful degradation
-   [ ] Set up per-stage observability
-   [ ] Test failure scenarios (agent timeout, network failure)
