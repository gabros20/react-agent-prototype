## Overview

Multimodal agents represent the evolution from text-only systems to agents that see, hear, and interact with the world. The key modalities are:

1. **Vision**: Screenshots, photos, diagrams, UI elements
2. **Audio**: Speech input/output, real-time voice
3. **Documents**: PDFs, charts, handwritten notes
4. **Generation**: Creating images, audio, video

The breakthrough in 2024-2025 is **unified agent workflows** where vision, audio, and text flow through the same reasoning loop, enabling agents that can look at a screen, hear a user, and take action.

**Key Research Findings** (2024-2025):

- **Claude Opus 4.5**: Best-in-class computer use, 77.8% on MMMU
- **GPT-4o**: 84.2% on MMMU, real-time audio via WebRTC
- **Gemini 2.0**: SOTA video understanding, 1M token context
- **Computer Use Agents**: 33% token reduction with UI-guided visual selection

**Date Verified**: January 2026

## The Problem: Text-Only Agents Are Limited

### The Classic Challenge

Text-only agents can't interact with visual interfaces, process spoken input, or understand documents with complex layouts.

```
User: "Click the submit button"
       ↓
Text Agent: "I cannot see the screen. Please describe the UI..."
       ↓
User: [Frustrated, describes button location in words]
       ↓
Agent: [Still can't take action - no mouse/keyboard]
```

**Problems**:

- ❌ **No visual understanding**: Can't see UIs, diagrams, or images
- ❌ **No voice interaction**: Requires text input/output only
- ❌ **Document blindness**: PDFs with tables/charts are opaque
- ❌ **No direct action**: Can't click, type, or navigate

### Why This Matters

The real world is multimodal:

- **Customer support**: Users share screenshots of errors
- **Accessibility**: Voice is more natural for many users
- **Enterprise**: Documents contain critical structured data
- **Automation**: Many tasks require UI interaction

## Core Concept

### What is a Multimodal Agent?

A multimodal agent processes multiple input types (vision, audio, text) and can produce multiple output types (text, actions, images, speech).

### Key Principles

1. **End-to-end perception**: Vision models see raw pixels, not DOM/accessibility trees
2. **Unified reasoning**: Same model handles vision + language + action
3. **Iterative verification**: Check results visually after each action
4. **Modality fusion**: Combine signals from multiple inputs for better decisions

const computerUseTools = {
  screenshot: tool({
    description: "Capture current screen",

    parameters: z.object({
      direction: z.enum(["up", "down"]),

**Agent Loop**:

```typescript
async function computerUseLoop(task: string, maxSteps: number = 20) {
  for (let step = 0; step < maxSteps; step++) {
    // Capture current state
    const screenshot = await captureScreen();

    // Ask model what to do
    const response = await model.generate({
      messages: [
        {
          role: "user",
          content: [
            { type: "image", image: screenshot },
            {
              type: "text",
              text: `Task: ${task}\nWhat action should I take? If task is complete, respond with DONE.`,
            },
          ],
        },
      ],
      tools: computerUseTools,
    });

    if (response.text.includes("DONE")) {
      return { success: true, steps: step };
    }

    // Execute tool calls
    for (const toolCall of response.toolCalls) {
      await executeTool(toolCall);
    }

    // Brief wait for UI to update
    await sleep(500);
  }

  return { success: false, reason: "Max steps reached" };
}
```

**Pros**:

- ✅ Works with any application (no API needed)
- ✅ Generalizes to unseen interfaces
- ✅ Human-like interaction pattern

**Cons**:

- ❌ Slower than API-based automation
- ❌ Requires visual verification each step
- ❌ UI changes can break workflows

**When to Use**: Legacy systems without APIs, web scraping, end-to-end testing.

### Pattern 2: Voice Agent (Real-Time Audio)

**Use Case**: Natural voice conversations with function calling.

OpenAI Realtime API and Gemini Live enable speech-to-speech with tool use.

```
┌─────────────────────────────────────────────────────────┐
│              VOICE AGENT ARCHITECTURE                   │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   User       ┌──────────────┐      Agent                │
│   Speech ──▶ │   WebSocket  │ ──▶ Actions               │
│              │   / WebRTC   │                           │
│   Speaker ◀──│              │ ◀── Speech                │
│              └──────────────┘                           │
│                                                         │
│   Key Events:                                           │
│   • input_audio_buffer.append (user speaking)           │
│   • transcription.completed (user finished)             │
│   • response.audio.delta (agent speaking)               │
│   • function_call (agent taking action)                 │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

```typescript
import { RealtimeClient } from "@openai/realtime-api-beta";

class VoiceAgent {
  private client: RealtimeClient;

  async initialize() {
    this.client = new RealtimeClient({
      apiKey: process.env.OPENAI_API_KEY,
      model: "gpt-4o-realtime",
    });

    await this.client.connect();

    // Configure tools
    this.client.updateSession({
      tools: [
        {
          type: "function",
          name: "lookup_order",
          description: "Look up customer order status",
          parameters: {
            type: "object",
            properties: {
              orderId: { type: "string" },
            },
          },
        },
        {
          type: "function",
          name: "transfer_to_human",
          description: "Transfer call to human agent",
          parameters: {
            type: "object",
            properties: {
              reason: { type: "string" },
            },
          },
        },
      ],
      voice: "alloy", // Voice preset
      vad: {
        // Voice activity detection
        enabled: true,
        threshold: 0.5,
        silence_duration_ms: 500,
      },
    });

    // Handle function calls
    this.client.on("function_call", async (call) => {
      const result = await this.executeFunction(call.name, call.arguments);
      await this.client.submitToolOutput(call.call_id, result);
    });
  }

  // Stream audio from microphone
  async sendAudio(chunk: ArrayBuffer) {
    await this.client.appendInputAudio(chunk);
  }

  // Receive audio responses
  onSpeech(callback: (audio: ArrayBuffer) => void) {
    this.client.on("response.audio.delta", (event) => {
      callback(event.delta);
    });
  }
}
```

**WebRTC vs WebSocket**:

| Transport   | Latency | Use Case                |
| ----------- | ------- | ----------------------- |
| **WebRTC**  | Lowest  | Browser voice agents    |
| **WebSocket** | Low   | Server-side, phone systems |

**Pros**:

- ✅ Natural voice interaction
- ✅ Sub-second response latency
- ✅ Built-in VAD (voice activity detection)

**Cons**:

- ❌ Higher API costs than text
- ❌ Requires audio infrastructure
- ❌ Ambient noise can affect quality

**When to Use**: Customer service, accessibility, hands-free interfaces.

### Pattern 3: Document Understanding

**Use Case**: Extracting structured data from PDFs, charts, and scanned documents.

Modern VLMs (Vision-Language Models) replace OCR with end-to-end visual understanding.

```
┌─────────────────────────────────────────────────────────┐
│          DOCUMENT PARSING APPROACHES                    │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  Traditional OCR:                                       │
│  PDF → OCR Engine → Raw Text → NLP → Structured Data   │
│  ❌ Loses layout information                            │
│  ❌ Fails on complex tables                             │
│  ❌ Can't understand charts                             │
│                                                         │
│  VLM-Based (LlamaParse, Unstructured.io):              │
│  PDF → Vision Model → Structured Data                   │
│  ✅ Understands layout                                  │
│  ✅ Extracts tables correctly                           │
│  ✅ Interprets charts/graphs                            │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

```typescript
// Using Claude Files API for document analysis
import Anthropic from "@anthropic-ai/sdk";

async function analyzeDocument(pdfPath: string) {
  const client = new Anthropic();

  // Upload file once
  const file = await client.files.create({
    file: fs.createReadStream(pdfPath),
    purpose: "vision",
  });

  // Query the document
  const response = await client.messages.create({
    model: "claude-3-opus-20240229",
    max_tokens: 4096,
    messages: [
      {
        role: "user",
        content: [
          {
            type: "document",
            source: { type: "file", file_id: file.id },
          },
          {
            type: "text",
            text: `Extract all tables from this document as JSON.
For each table:
- Include headers
- Preserve cell values exactly
- Note the page number`,
          },
        ],
      },
    ],
  });

  return JSON.parse(response.content[0].text);
}
```

**Extraction Tool**:

```typescript
const documentTool = tool({
  description: "Extract structured data from a document",
  parameters: z.object({
    documentId: z.string(),
    extractionType: z.enum(["tables", "text", "key_values", "all"]),
    schema: z.record(z.any()).optional(), // Expected output schema
  }),
  execute: async ({ documentId, extractionType, schema }) => {
    const doc = await getDocument(documentId);

    const prompt = schema
      ? `Extract data matching this schema: ${JSON.stringify(schema)}`
      : `Extract ${extractionType} from this document`;

    const result = await visionModel.generate({
      messages: [
        {
          role: "user",
          content: [
            { type: "document", source: doc },
            { type: "text", text: prompt },
          ],
        },
      ],
    });

    return result;
  },
});
```

**Pros**:

- ✅ Handles complex layouts (multi-column, nested tables)
- ✅ Understands context (chart title → data meaning)
- ✅ Works on scanned/handwritten documents

**Cons**:

- ❌ Higher latency than OCR (~6s vs ~1s)
- ❌ More expensive per page
- ❌ May hallucinate values in unclear areas

**When to Use**: Invoice processing, report analysis, form extraction.

### Multimodal RAG Pattern

```typescript
// RAG system that handles text, images, and documents
interface MultimodalDocument {
  type: "text" | "image" | "pdf";
  content: string | Buffer;
  embedding?: number[];
  metadata: Record<string, any>;
}

async function indexMultimodalDocument(doc: MultimodalDocument) {
  let embedding: number[];

  switch (doc.type) {
    case "text":
      embedding = await embedText(doc.content as string);
      break;

    case "image":
      // Use CLIP or similar for image embeddings
      const imageDescription = await describeImage(doc.content as Buffer);
      embedding = await embedText(imageDescription);
      break;

    case "pdf":
      // Extract text + images, embed combined description
      const extracted = await extractPDF(doc.content as Buffer);
      embedding = await embedText(extracted.summary);
      break;
  }

  await vectorStore.upsert({
    id: doc.id,
    embedding,
    metadata: { ...doc.metadata, type: doc.type },
  });
}

async function multimodalSearch(query: string, types?: string[]) {
  const queryEmbedding = await embedText(query);

  const results = await vectorStore.query({
    embedding: queryEmbedding,
    topK: 10,
    filter: types ? { type: { $in: types } } : undefined,
  });

  return results;
}
```

## When to Use This Pattern

### ✅ Use When:

1. **UI Automation without APIs**
   - Legacy applications with no programmatic access
   - Cross-platform desktop automation
   - Example: Automating data entry into enterprise software

2. **Voice-First Interfaces**
   - Hands-free operation required
   - Accessibility requirements
   - Example: Customer service hotlines, in-car assistants

3. **Document Processing**
   - Complex layouts (tables, charts, mixed content)
   - Need to understand context, not just extract text
   - Example: Invoice processing, contract analysis

### ❌ Don't Use When:

1. **API Available**
   - Direct API is faster, cheaper, more reliable
   - Computer use should be last resort
   - Better alternative: Use the API

2. **Text Sufficient**
   - Task doesn't require visual understanding
   - Adding vision increases cost without benefit
   - Better alternative: Text-only agent

3. **Low Latency Critical**
   - Real-time requirements under 500ms
   - Vision processing adds 1-3 seconds
   - Better alternative: Pre-processed pipelines

### Decision Matrix

| Your Situation           | Recommended Approach               |
| ------------------------ | ---------------------------------- |
| Automate legacy desktop  | Computer use agent                 |
| Voice customer support   | Realtime audio + function calling  |
| Extract from PDFs        | VLM-based document parsing         |
| Generate marketing images| DALL-E 3 tool                      |

## Production Best Practices

### 1. Optimize Vision Token Usage

Vision tokens are expensive. Reduce image size when full resolution isn't needed.

```typescript
// Resize before sending
const optimizedImage = await sharp(screenshot)
  .resize(1568, 1568, { fit: "inside" }) // Claude's optimal size
  .jpeg({ quality: 80 })
  .toBuffer();
```

**Why**: Full-resolution screenshots can cost 10x more tokens.
**Impact**: 50-70% cost reduction with minimal accuracy loss.

### 2. Cache Document Analysis

Don't re-analyze the same document repeatedly.

```typescript
// Use Files API for repeated queries
const file = await anthropic.files.create({ file: pdf });

// Multiple queries reuse the same upload
const query1 = await analyze(file.id, "Extract tables");
const query2 = await analyze(file.id, "Summarize findings");
const query3 = await analyze(file.id, "Find key dates");
```

**Why**: Document processing is expensive.
**Impact**: 3-5x cost reduction for multi-query workflows.

### 3. Graceful Audio Fallback

Voice systems should handle transcription failures gracefully.

```typescript
client.on("transcription.error", async (error) => {
  // Fallback to text input
  const fallbackResponse = await textModel.generate({
    prompt: "I couldn't understand that. Could you type your request?",
  });

  // Speak the fallback
  await synthesizeAndPlay(fallbackResponse);
});
```

**Why**: Audio quality varies, failures happen.
**Impact**: Prevents user abandonment on transcription failures.

### 4. Common Pitfalls

#### ❌ Pitfall 1: Trusting element grounding

Vision models struggle to locate exact pixel coordinates.

**Problem**: Click actions miss the target element.

#### ✅ Solution: Combine with accessibility tree

```typescript
// Get both visual understanding AND structured element data
const screenshot = await captureScreen();
const accessibilityTree = await getAccessibilityTree();

const action = await model.generate({
  messages: [
    {
      role: "user",
      content: [
        { type: "image", image: screenshot },
        {
          type: "text",
          text: `Visual context above. Accessibility tree:
${formatTree(accessibilityTree)}

Click the submit button. Use element ID from tree, not coordinates.`,
        },
      ],
    },
  ],
});
```

**Benefit**: 75% improvement in click accuracy.

## Trade-offs & Considerations

### Advantages

1. **Universal interaction**: Works with any interface, no API needed
2. **Human-like**: Matches how humans interact with computers
3. **Rich understanding**: Vision captures context text can't

### Disadvantages

1. **Cost**: Vision tokens 5-10x more expensive than text
2. **Latency**: Image processing adds 1-3 seconds per step
3. **Reliability**: Visual grounding has 75% accuracy, not 99%

### Cost Analysis

**Scenario**: Process 1,000 documents/month

**Traditional OCR + NLP**:

- OCR: 1,000 pages × $0.01 = $10
- NLP processing: $50
- **Total**: $60/month

**VLM-Based Processing**:

- Vision analysis: 1,000 pages × $0.10 = $100
- Accuracy improvement: +20%
- Manual correction saved: -$200 (fewer errors)
- **Total**: $100 - $200 = -$100 (net savings)
- **ROI**: Higher accuracy pays for itself

## Key Takeaways

1. **Vision enables new capabilities** - Computer use, document understanding, UI analysis
2. **Audio is natural** - Voice agents feel more human than text chat
3. **Cost matters** - Optimize image size, cache results, use vision only when needed
4. **Combine modalities** - Vision + accessibility tree beats vision alone
5. **Verify visually** - Always capture screenshot after action to verify
