## Overview

Reflexion enables LLM agents to learn from trial-and-error by converting feedback (success/failure signals, environment responses, self-evaluation) into verbal reflections stored in memory. Unlike traditional reinforcement learning that updates model weights, Reflexion uses natural language to encode lessons learned, allowing the agent to improve within a conversation without fine-tuning.

The pattern follows a simple loop: **Generate** an output, **Critique** it against criteria, and **Refine** based on the critique. The key innovation is persisting reflections across attempts, so the agent doesn't repeat the same mistakes.

**Key Research Findings** (2024-2025):

- **+22% AlfWorld**: Reflexion improves task completion on interactive environments (Shinn et al. 2023)
- **+20% HotPotQA**: Multi-hop reasoning accuracy significantly improves with reflection
- **+11% HumanEval**: Code generation pass@1 improves from 80.1% to 91.0%
- **2-3 Iterations Optimal**: Most gains occur in first 2-3 refinement cycles
- **External Feedback Critical**: Self-correction without verification degrades reasoning by 3-4% (Huang 2024)

**Date Verified**: 2025-01-07

## The Problem: Agents Don't Learn from Mistakes

### The Classic Challenge

Without reflection, agents repeat the same errors across attempts:

```
┌─────────────────────────────────────────────────────────────┐
│                AGENT WITHOUT REFLECTION                      │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  Task: "Write a function to find palindromes in a list"     │
│                                                              │
│  Attempt 1:                                                  │
│    def find_palindromes(lst):                                │
│        return [x for x in lst if x == x[::-1]]               │
│    ❌ Error: Can't slice integers                            │
│                                                              │
│  Attempt 2: (no memory of previous error)                   │
│    def find_palindromes(lst):                                │
│        return [x for x in lst if x == x[::-1]]               │
│    ❌ Same error: Can't slice integers                       │
│                                                              │
│  Attempt 3: (still no learning)                             │
│    def find_palindromes(lst):                                │
│        return [item for item in lst if item == item[::-1]]   │
│    ❌ Same error: Can't slice integers                       │
│                                                              │
│  Agent is stuck in a loop, repeating the same mistake       │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**Problems**:

- ❌ **No Error Memory**: Agent forgets what went wrong in previous attempts
- ❌ **Repeated Mistakes**: Same errors occur attempt after attempt
- ❌ **Wasted Tokens**: Generating identical failing outputs
- ❌ **No Improvement Signal**: Agent doesn't know what to fix
- ❌ **Poor User Experience**: Users see the same failures repeatedly

### Why This Matters

In production:
- **30-40% of agent failures** are repeated errors that could be avoided with reflection
- **Token costs multiply** when agents retry without learning
- **User trust erodes** when agents make the same mistake multiple times
- **Complex tasks fail** because agents can't learn from intermediate feedback

## Core Concept

### What is Reflexion?

Reflexion is a three-component system:

```
┌─────────────────────────────────────────────────────────────┐
│                    REFLEXION ARCHITECTURE                    │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                    ACTOR                                 ││
│  │  Generates actions/outputs based on task + reflections  ││
│  └──────────────────────┬──────────────────────────────────┘│
│                         ↓                                    │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                  EVALUATOR                               ││
│  │  Scores output quality (binary, scalar, or LLM-based)   ││
│  └──────────────────────┬──────────────────────────────────┘│
│                         ↓                                    │
│  ┌─────────────────────────────────────────────────────────┐│
│  │                SELF-REFLECTION                           ││
│  │  Generates verbal feedback on what went wrong/right     ││
│  │  Stores reflection in episodic memory                    ││
│  └──────────────────────┬──────────────────────────────────┘│
│                         ↓                                    │
│  ┌─────────────────────────────────────────────────────────┐│
│  │              EPISODIC MEMORY                             ││
│  │  Stores reflections for future attempts                  ││
│  │  "Previous attempt failed because..."                    ││
│  └─────────────────────────────────────────────────────────┘│
│                                                              │
│  Loop continues until:                                       │
│    - Evaluator returns success                               │
│    - Max iterations reached                                  │
│    - No improvement detected                                 │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### The Generate → Critique → Refine Loop

```
┌─────────────────────────────────────────────────────────────┐
│              GENERATE → CRITIQUE → REFINE LOOP              │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  ┌────────────────────────────────────────────────────┐     │
│  │  ITERATION 1                                        │     │
│  │  ─────────────                                      │     │
│  │  Generate: def find_palindromes(lst):               │     │
│  │              return [x for x in lst if x == x[::-1]]│     │
│  │                                                      │     │
│  │  Critique: "Failed - can't slice integers.          │     │
│  │            Need to convert to string first."        │     │
│  │                                                      │     │
│  │  Reflection stored: "Must convert elements to       │     │
│  │    strings before checking palindrome property"     │     │
│  └────────────────────────────────────────────────────┘     │
│                         ↓                                    │
│  ┌────────────────────────────────────────────────────┐     │
│  │  ITERATION 2                                        │     │
│  │  ─────────────                                      │     │
│  │  Context: Previous reflection injected              │     │
│  │                                                      │     │
│  │  Generate: def find_palindromes(lst):               │     │
│  │              return [x for x in lst                 │     │
│  │                      if str(x) == str(x)[::-1]]     │     │
│  │                                                      │     │
│  │  Critique: "Passes tests! Solution works."          │     │
│  └────────────────────────────────────────────────────┘     │
│                         ↓                                    │
│                     SUCCESS ✓                               │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

### Key Components

**1. Actor (Generator)**
- Produces actions or outputs
- Receives task description + previous reflections
- Can be any LLM or agent system

**2. Evaluator**
- Assesses output quality
- Can be binary (pass/fail), scalar (0-10), or descriptive
- Often uses test execution, external validators, or LLM judges

**3. Self-Reflection Generator**
- Analyzes failures to produce learning signal
- Generates natural language reflections
- Key insight: Verbal RL without weight updates

**4. Episodic Memory**
- Stores reflections across attempts
- Injected into actor's context
- Enables cross-attempt learning

### Key Principles

1. **Verbal Reinforcement**: Learning happens through language, not gradient updates
2. **Explicit Reflection**: Agent must articulate what went wrong
3. **Memory Persistence**: Reflections survive across attempts
4. **Bounded Iteration**: Limit refinement cycles to prevent loops
5. **External Feedback Required**: Pure self-correction often fails

## Iteration Control

### Why Limit Iterations?

Research shows diminishing returns after 2-3 iterations:

```
┌─────────────────────────────────────────────────────────────┐
│              ITERATION vs. IMPROVEMENT                       │
├─────────────────────────────────────────────────────────────┤
│                                                              │

│  │  │   │  │   │  │   │  │   │  ┌───┐  ┌───┐              │
```

### Stopping Criteria

```typescript
interface IterationConfig {
  maxIterations: number;        // Hard limit (typically 3)
  targetScore: number;          // Stop if achieved (e.g., 0.95)
  minImprovement: number;       // Stop if delta below (e.g., 0.02)
  consecutiveNoImprovement: number; // Stop after N flat iterations
}

function shouldContinue(
  history: IterationHistory[],
  config: IterationConfig
): boolean {
  const current = history.at(-1);
  if (!current) return true;

  // Hard iteration limit
  if (history.length >= config.maxIterations) return false;

  // Target score achieved
  if (current.score >= config.targetScore) return false;

  // Check for improvement stagnation
  if (history.length >= 2) {
    const previous = history.at(-2)!;
    const improvement = current.score - previous.score;
    if (improvement < config.minImprovement) {
      const noImprovementCount = countConsecutiveNoImprovement(history, config);
      if (noImprovementCount >= config.consecutiveNoImprovement) {
        return false;
      }
    }
  }

  return true;
}
```

### Best Output Selection

**Critical**: Track all outputs and return the best, not the last:

```typescript
interface IterationHistory {
  iteration: number;
  output: string;
  score: number;
  reflection: string;
}

function selectBestOutput(history: IterationHistory[]): string {
  // Return highest-scoring output, not most recent
  const best = history.reduce((best, current) =>
    current.score > best.score ? current : best
  );
  return best.output;
}
```


### Reflection Depth by Context

```typescript
type ReflectionDepth = 'minimal' | 'standard' | 'deep' | 'abort';

function determineReflectionDepth(
  score: number,
  iteration: number,
  errorType: string
): ReflectionDepth {
  // Already tried multiple times with poor results
  if (iteration >= 3 && score < 0.5) return 'abort';

  // Fundamental error requiring different approach
  if (errorType === 'WRONG_APPROACH') return 'deep';

  // High score, just polish
  if (score >= 0.8) return 'minimal';

  // Medium score, standard improvement
  if (score >= 0.5) return 'standard';

  // Low score, need deeper analysis
  return 'deep';
}
```

## Implementation Patterns

### Pattern 1: Basic Reflexion Loop

**Use Case**: Code generation with test feedback

```typescript
import { generateText, generateObject } from 'ai';
import { openai } from '@ai-sdk/openai';
import { z } from 'zod';

interface ReflexionState {
  task: string;
  attempts: Array<{
    output: string;
    score: number;
    reflection: string;
  }>;
}

const ReflectionSchema = z.object({
  whatWentWrong: z.string(),
  whatToTryNext: z.string(),
  lessonLearned: z.string(),
});

async function reflexionLoop(
  task: string,
  evaluate: (output: string) => Promise<{ score: number; feedback: string }>,
  maxIterations = 3
): Promise<string> {
  const state: ReflexionState = { task, attempts: [] };

  for (let i = 0; i < maxIterations; i++) {
    // Generate output with reflection context
    const reflectionContext = state.attempts
      .map(a => `Previous attempt failed: ${a.reflection}`)
      .join('\n');

    const { text: output } = await generateText({
      model: openai('gpt-4o'),
      prompt: `${task}

${reflectionContext ? `Learn from previous failures:\n${reflectionContext}` : ''}`,
    });

    // Evaluate
    const { score, feedback } = await evaluate(output);

    // Success check
    if (score >= 0.95) {
      return output;
    }

    // Generate reflection
    const { object: reflection } = await generateObject({
      model: openai('gpt-4o'),
      schema: ReflectionSchema,
      prompt: `Analyze this failure and learn from it.

Task: ${task}
Output: ${output}
Feedback: ${feedback}
Score: ${score}

What went wrong and what should be tried next?`,
    });

    state.attempts.push({
      output,
      score,
      reflection: reflection.lessonLearned,
    });
  }

  // Return best attempt
  return state.attempts.reduce((best, curr) =>
    curr.score > best.score ? curr : best
  ).output;
}
```

### Pattern 2: Self-Refine (No External Feedback)

**Use Case**: Creative writing, style improvement

```typescript
async function selfRefineLoop(
  task: string,
  criteria: string[],
  maxIterations = 3
): Promise<string> {
  let currentOutput = await generateText({
    model: openai('gpt-4o'),
    prompt: task,
  }).then(r => r.text);

  for (let i = 0; i < maxIterations; i++) {
    // Self-critique
    const { object: critique } = await generateObject({
      model: openai('gpt-4o'),
      schema: z.object({
        issues: z.array(z.object({
          criterion: z.string(),
          problem: z.string(),
          suggestion: z.string(),
        })),
        overallScore: z.number().min(0).max(1),
      }),
      prompt: `Critique this output against criteria: ${criteria.join(', ')}

Output: ${currentOutput}

Find specific issues and suggest improvements.`,
    });

    // Stop if good enough
    if (critique.overallScore >= 0.9 || critique.issues.length === 0) {
      break;
    }

    // Refine based on critique
    currentOutput = await generateText({
      model: openai('gpt-4o'),
      prompt: `Improve this output based on feedback:

Original: ${currentOutput}

Issues to fix:
${critique.issues.map(i => `- ${i.problem}: ${i.suggestion}`).join('\n')}`,
    }).then(r => r.text);
  }

  return currentOutput;
}
```

### Pattern 3: Reflexion with Episodic Memory

**Use Case**: Long-running agent tasks with persistent learning

```typescript
interface EpisodicMemory {
  store(taskType: string, reflection: string): void;
  retrieve(taskType: string, limit: number): string[];
}

async function reflexionWithMemory(
  task: string,
  taskType: string,
  memory: EpisodicMemory,
  evaluate: (output: string) => Promise<EvaluationResult>
): Promise<string> {
  // Retrieve relevant past reflections
  const pastReflections = memory.retrieve(taskType, 5);

  const { text: output } = await generateText({
    model: openai('gpt-4o'),
    prompt: `${task}

Past lessons learned:
${pastReflections.map(r => `- ${r}`).join('\n')}`,
  });

  const result = await evaluate(output);

  if (result.score < 0.9) {
    // Generate and store reflection for future
    const { object } = await generateObject({
      model: openai('gpt-4o'),
      schema: ReflectionSchema,
      prompt: `Generate a lesson learned from this attempt.

Task: ${task}
Output: ${output}
Score: ${result.score}
Feedback: ${result.feedback}`,
    });

    memory.store(taskType, object.lessonLearned);
  }

  return output;
}
```

## Research & Benchmarks

### Academic Research (2024-2025)

#### Reflexion (Shinn et al., NeurIPS 2023)

- **Core Innovation**: Store verbal reflections in episodic memory
- **Results**: +22% AlfWorld, +20% HotPotQA, +11% HumanEval
- **Key Insight**: Binary success/failure signal sufficient to trigger useful reflection

#### Self-Refine (Madaan et al., NeurIPS 2023)

- **Core Innovation**: LLM critiques own output, then refines
- **Results**: +20% code optimization, +13% dialogue, +16% sentiment
- **Key Insight**: Average convergence in 2.3 iterations

#### LLMs Cannot Self-Correct Reasoning Yet (Huang et al., ICLR 2024)

- **Core Claim**: Without external feedback, LLMs fail to improve reasoning
- **Results**: GPT-4 GSM8K drops from 92% to 89% with self-correction
- **Critical Distinction**: With feedback → works; without feedback → fails

### Production Benchmarks

| Method | HumanEval | AlfWorld | GSM8K (no feedback) |
|--------|-----------|----------|---------------------|
| Zero-shot | 67% | 65% | 92% |
| + Self-Refine | 79% | 71% | 89% ❌ |
| + Reflexion (with tests) | 91% | 87% | N/A |

### When Reflection Helps vs. Hurts

| Task Type | With External Feedback | Without Feedback |
|-----------|----------------------|------------------|
| **Code generation** | ✅ +11-24% | ⚠️ Marginal |
| **Interactive tasks** | ✅ +15-22% | N/A |
| **Math reasoning** | ✅ With calculator | ❌ -3-4% |
| **Factual QA** | ✅ With search | ❌ Degrades |
| **Creative writing** | ✅ With rubric | ⚠️ Variable |

## When to Use This Pattern

### ✅ Use When:

1. **External Feedback Available** (tests, validators, environment)
2. **Clear Quality Criteria** (formatting, correctness, style)
3. **Task Allows Iteration** (not time-critical)
4. **Errors Are Correctable** (not systematic blind spots)

### ❌ Don't Use When:

1. **No External Verification** (pure reasoning without feedback)
2. **Single-Shot Required** (latency-critical applications)
3. **Near Ceiling Performance** (already 95%+ accuracy)
4. **Systematic Model Weakness** (same error type repeatedly)

### Decision Matrix

| Feedback Available | Task Type | Recommendation |
|-------------------|-----------|----------------|
| Tests/validators | Code | ✅ Reflexion |
| Environment | Interactive | ✅ Reflexion |
| LLM judge | Creative | ✅ Self-Refine (2-3 iterations) |
| None | Reasoning | ❌ Self-Consistency voting instead |

### 3. Track Best Output

```typescript
// ✅ Good: Return best scoring
const best = history.reduce((a, b) => a.score > b.score ? a : b);

// ❌ Bad: Return last iteration
const last = history.at(-1); // May have degraded
```

### 4. Separate Generation and Critique

```typescript
// ✅ Good: Different prompts/models
const output = await generator.generate(task);
const critique = await critic.evaluate(output);

// ❌ Bad: Same prompt for both
const output = await model.generate(task + "Then critique yourself");
```

### 5. Monitor for Degradation

Track score trajectory—if scores decrease, stop immediately:

```typescript
if (currentScore < previousScore - 0.05) {
  console.warn('Score degradation detected, stopping');
  return selectBestOutput(history);
}
```

## Key Takeaways

1. **External feedback is essential**: Self-correction without verification often degrades output
2. **2-3 iterations is optimal**: Research consistently shows diminishing returns after
3. **Track best output**: Later iterations may be worse; keep highest-scoring
4. **Task selection matters**: Use for code, interactive tasks; avoid for pure reasoning
5. **Separate generation from critique**: Different prompts/models for each role
6. **Episodic memory prevents repetition**: Store lessons across attempts

**Quick Implementation Checklist**:

- [ ] Ensure feedback signal available (tests, validators, judges)
- [ ] Limit iterations to 2-3 maximum
- [ ] Track scores across iterations, return best
- [ ] Use separate critique prompt/model
- [ ] Avoid pure self-correction for reasoning tasks
- [ ] Monitor for over-confidence degradation
- [ ] Store reflections in episodic memory for cross-task learning
